# nixos-config

## Making a change

1. Edit the relevant file (see **Layout** below for which one).
2. Apply it on the machine you're sitting at:
   ```
   sudo nixos-rebuild switch --flake ~/nixos-config#<machine>
   ```
   `<machine>` is `nixos` or `t14` (see **Machines**). If it fails, nothing
   on the running system changes — fix the error and try again.
3. If it worked and you're happy with it, commit:
   ```
   git add -A
   git commit -m "describe the change"
   ```

That's the whole loop. Nothing here needs a reboot except kernel/driver
changes (rare); `switch` takes effect immediately for everything else.

Before committing something non-trivial, it's worth running:
```
nix flake check   # catches eval errors in both hosts' configs
nix fmt           # auto-formats every .nix file
```

## Layout

- `flake.nix` — inputs (`nixpkgs` stable, `nixpkgs-unstable`, `home-manager`,
  `cosmic-manager`) and one `nixosConfigurations` entry per machine, sharing
  the same base modules. Also defines the `formatter` and `devShells.default`
  used by the tooling below.
- `configuration.nix` — shared system config (desktop, locale, packages) used
  by every host. Uses `pkgs-unstable.jetbrains-toolbox` since the stable
  version's download URL is dead.
- `home.nix` — home-manager config for `alex`: packages, dconf (GNOME)
  settings, COSMIC desktop settings, bash setup.
- `home/` — files `home.nix` points at instead of inlining them, so they get
  normal syntax highlighting/linting as their own file type:
  - `bashrc-extra.sh`, `resizer.sh` — plain bash, pulled in via
    `builtins.readFile`.
  - `cosmic-shortcuts-custom.ron` — COSMIC's custom-keyboard-shortcuts file.
    This one is special; see **COSMIC shortcuts** below.
- `hosts/<name>/default.nix` — per-machine config: hostname + anything
  specific to that box.
- `hosts/<name>/hardware-configuration.nix` — machine-specific, autogenerated
  by `nixos-generate-config`.

## Machines

- `nixos` — the original machine (Intel CPU).
- `t14` — ThinkPad T14 (AMD Ryzen AI 350).

```
sudo nixos-rebuild switch --flake ~/nixos-config#nixos
# or
sudo nixos-rebuild switch --flake ~/nixos-config#t14
```

A nicer alternative is [`nh`](https://github.com/nix-community/nh) (installed
via `home.nix`), which shows a readable diff of what's changing:
```
nh os switch ~/nixos-config#<machine>
```

## COSMIC shortcuts

Most COSMIC desktop settings are declared normally in `home.nix` under
`wayland.desktopManager.cosmic` via `cosmic-manager`, and behave like
everything else here: edit the Nix, `switch`, done.

Custom keyboard shortcuts are the one exception — `home/cosmic-shortcuts-custom.ron`
is symlinked directly to COSMIC's real config file
(`~/.config/cosmic/com.system76.CosmicSettings.Shortcuts/v1/custom`) instead
of being generated by `cosmic-manager`. This means:

- You can add/change a shortcut **either** through the COSMIC Settings GUI
  **or** by editing `home/cosmic-shortcuts-custom.ron` directly — both write
  to the same file, and both take effect immediately without a rebuild.
- `git status` afterwards will show the diff, so commit it like any other
  change.
- Unlike the rest of `home.nix`, this file isn't type-checked by Nix — a
  malformed edit just gets silently ignored by COSMIC rather than caught by
  `nix flake check`.

This tradeoff is deliberate: it's the only way to let the GUI and the repo
agree on shortcuts without a rebuild reverting GUI changes. Don't move other
COSMIC settings out to raw files this way unless you specifically want the
same GUI-editable behavior for them.

## Editor setup

`home.nix` installs `nixd` (Nix language server), `nixfmt`, `statix`
(linter), `deadnix` (finds unused bindings), and `nh`. `.vscode/settings.json`
points VS Code's Nix extension at `nixd`, configured to evaluate this flake's
actual options — so hovering/autocompleting inside `home.nix` or
`configuration.nix` shows real option docs, including ones added by
`cosmic-manager`.

A `.envrc` (`use flake`) is also included: with `direnv` installed and its
VS Code/shell integration enabled, entering this directory automatically
gets you `nixd` & co. on `$PATH` even before you've run `switch` on a new
machine.

## Updating inputs

Bumps `flake.lock`, then rebuild:
```
nix flake update --flake ~/nixos-config
sudo nixos-rebuild switch --flake ~/nixos-config#<machine>
```

## Adding a new machine

1. Boot a NixOS installer on the machine, partition/mount disks, then run:
   ```
   nixos-generate-config --root /mnt
   ```
2. Create `hosts/<name>/` in this repo and copy the generated
   `hardware-configuration.nix` into it.
3. Add a `hosts/<name>/default.nix`:
   ```nix
   { imports = [ ./hardware-configuration.nix ]; networking.hostName = "<name>"; }
   ```
4. Add `nixosConfigurations.<name> = mkHost ./hosts/<name>/default.nix;` in `flake.nix`.
